# P06 native media checkpoint

This is a standalone synthetic qualification of CUDA → NV12 → external NVENC → LiveKit C++ pre-encoded H.264 → actual Chromium decoding/presentation. The product API still uses the P04/P05 raw-copy reference. Native Qwen/session/selected-avatar integration, cancellation, packaging, virtual devices and co-load acceptance remain unfinished. P06 is **in_progress**.

## Qualified environment and ownership

Observed RTX 4070 Ti SUPER 16 GiB, NVIDIA 580.178.04, CUDA 12.8.93, GCC 14.3.1, CMake 3.31.11, Rust 1.99.0; Fedora FFmpeg 7.1.4 (`libavcodec` 61.19.101 / `libavutil` 59.39.100). The existing isolated CUDA header overlay from P02 is used; no system NVIDIA header/driver was replaced. GPU architecture 89 is explicit, not a portable binary claim.

One owner thread retains its CUDA context, one RGBA surface, three NV12 surfaces, renderer/conversion streams and NVENC. Conversion waits on the renderer event; NVENC submission waits for completed conversion because this FFmpeg boundary does not consume the application event. A retained input slot cannot be overwritten. Complete access units retain their original PTS and own CPU encoded bytes. The SDK then copies encoded payloads synchronously. This is not zero-copy transport. An unexpected delayed/reordered packet terminates the probe rather than silently remapping timestamps.

The publisher uses direct 10 ms / 480-sample mono audio capture without a sender queue. Video runs independently every 1,600 samples. Both schedules derive from one 48 kHz integer ledger and one monotonic origin. LiveKit rate feedback changes encoder bit allocation; it does not change the renderer clock. Keyframe requests and the one-second recovery interval force independently decodable H.264 units. Publication SIDs come from `publication()->sid()`; the pinned C++ track object's `sid()` remains `TR_unknown`.

Video metadata carries frame ID and source PTS through the SFU to browser `requestVideoFrameCallback` lookup. Preparation consists of 30 black video frames and 48,000 zero audio samples, followed by exactly 240 valid pattern frames / 384,000 valid tone samples. Preparation is never meaningful-response credit or excluded from a cold-start measurement. EOF's sender event is not receiver or acoustic acknowledgment. Opus receiver sample totals/underflow concealment are not a PCM conservation proof.

The pinned JS SDK enables Chromium insertable streams for the entire receiver PC when frame metadata is requested, but only installs a video transform. The harness explicitly forwards encoded audio through an identity stream. Without it audio stalls; this compatibility workaround is confined to qualification. Normal preview playback is unchanged.

## Reproduction

From the repository root, with the already qualified P04 loopback SFU/API running and the P02 CUDA overlay present:

```sh
git -c filter.lfs.smudge= -c filter.lfs.required=false clone --branch v1.11.0 --depth 1 https://github.com/livekit/client-sdk-cpp.git v2/var/sources/livekit-cpp-v1.11.0
git -C v2/var/sources/livekit-cpp-v1.11.0 submodule update --init client-sdk-rust
git -C v2/var/sources/livekit-cpp-v1.11.0/client-sdk-rust submodule update --init yuv-sys/libyuv livekit-protocol/protocol
v2/.venv/bin/python v2/scripts/build_livekit_cpp.py
cmake -S v2/native/media -B v2/var/build/native-media -G Ninja \
  -DCMAKE_BUILD_TYPE=Release -DCMAKE_CXX_COMPILER=/usr/bin/g++-14 \
  -DCMAKE_CUDA_COMPILER=/usr/local/cuda-12.8/bin/nvcc \
  -DCMAKE_CUDA_HOST_COMPILER=/usr/bin/g++-14 -DCUDAToolkit_ROOT=/usr/local/cuda-12.8 \
  -DCMAKE_CUDA_ARCHITECTURES=89 \
  -DCMAKE_CUDA_FLAGS=-I"$PWD/v2/var/toolchains/cuda-12.8-include" \
  -DTHA_CUDA_INCLUDE_OVERLAY="$PWD/v2/var/toolchains/cuda-12.8-include" \
  -DTHA_LIVEKIT_SOURCE="$PWD/v2/var/sources/livekit-cpp-v1.11.0" \
  -DTHA_LIVEKIT_BUILD="$PWD/v2/var/build/livekit-cpp"
cmake --build v2/var/build/native-media --parallel 4
v2/var/build/native-media/tha_encoder_contract v2/var/build/native-media/media_kernels.ptx
cd v2/web
npx playwright test --config playwright.native.config.ts --reporter=json > ../var/p06/playwright-native-clock.json
```

The build script refuses an unavailable/unqualified installed compiler or wrong source revision; it does not provision a compiler. Cargo/CMake software downloads are possible on a fresh cache. The browser harness creates bounded two-minute room grants from the private local config in Node, never in browser code. It launches and retires its own publisher, and keeps tokens/logs/captures under ignored private `var/p06/`.

From the repository root, trace/export commands actually run:

```sh
/usr/local/bin/nsys profile --trace=cuda,nvtx --cuda-memory-usage=true \
  --sample=none --cpuctxsw=none --force-overwrite=true \
  --output=v2/var/p06/encoder-trace-metadata \
  v2/var/build/native-media/tha_encoder_probe \
  v2/var/build/native-media/media_kernels.ptx 300 v2/var/p06/pattern-traced-metadata.h264
/usr/local/bin/nsys export --type sqlite --force-overwrite=true \
  --output=v2/var/p06/encoder-trace-metadata.sqlite v2/var/p06/encoder-trace-metadata.nsys-rep
v2/.venv/bin/python v2/scripts/qualify_p06.py \
  --browser-report v2/var/p06/playwright-native-clock.json \
  --trace v2/var/p06/encoder-trace-metadata.sqlite \
  --output /tmp/p06-new-evidence.json
```

The exporter refuses overwriting evidence and rejects an empty/wrong trace. It can record failed checks without turning them into phase completion. Raw traces, elementary streams and screenshots stay private.

## Actual observations and remaining gates

- Core offline tests: **213 passed in 5.15 s**; `npx tsc --noEmit` passed. GPU contracts passed three owner lifetimes / 270 encoded frames, three failed module initializations, foreign-thread rejection, duplicate/backward PTS rejection and forced-keyframe recovery. These are short lifetime checks, not a soak.
- Browser: **2 passed in 24.28 s**, zero retries. Prepared clean run presented all **240/240 valid frame IDs**, with source PTS mapping; decoder reported 268/270 including preparation, zero dropped frames/packets. Deliberate resubscription recovered and presented 202 valid frames across both bindings; that planned outage is a separate cohort. Both received nonzero decoded audio. Physical A/V skew remains unmeasured.
- Clean/recovery maximum scheduling lateness: **0.122 / 0.760 ms** in these short observations. They are source scheduler samples, not conversational latency quantiles. The tone/pattern is synthetic, not avatar quality evidence.
- Sampled publisher GPU peak: **857 MiB** at 200 ms polling in both cohorts, **fails the planned 512 MiB encoder budget**. Loading peaks, Qwen/motion/render co-load, desktop reserve and capacity remain unqualified. Three small input surfaces do not describe total driver/NVENC memory.
- CUDA trace: 300 render + 300 NV12 conversion + **600 NVENC `Convert_PL2BL` kernels**. Four CUDA allocation calls occurred before the first kernel, none afterward; no CUDA memcpy API/activity was observed in this isolated trace. This supports no observed raw-frame readback in that exact CUDA-visible boundary. Encoded CPU copies, driver-internal behavior and other processes remain outside that claim. File decoding confirmed 300 Constrained Baseline H.264 frames, 512×512, BT.709 limited-range, no B-frames configured.
- Earlier failures are retained privately: wrong publication SID at teardown; encoder-feedback/render-clock coupling; mixed outage/baseline counting; unprepared cold start (236/240 decoded); missing audio transform; buffered-clock presentation (209/240 valid frames presented). The independent direct sample clock fixed the latter without lowering the 237/240 clean presentation diagnostic.
