## Implemented boundary

- [Canonical mesh loader](../src/talkinghead_v2/assets/avatar.py): offline hash verification, tenant/approval/use metadata, separate provenance/terms, neutral geometry/topology and basis/jaw bindings, exact named blendshape order, bounds and camera/pose conventions. Unknown representations, topology changes, coefficient truncation/padding, invalid face indices, reflected camera rotations and symlinked payloads fail. This is an operator-controlled local import check; it does not implement P05's durable authorization/revocation service.
- [Claire context frontend](../src/talkinghead_v2/providers/motion/claire.py): one session/epoch's ordered 16 kHz input, bounded 20 ms pushes, at most 8,640 retained samples, 8,320-sample windows centered at offset 4,160, explicit left/EOF padding and cancellation. Padding is model context only. Targets never extend into padded audio. The frontend **does not execute Claire** or fabricate neural motion.
- [Retarget calibration](../src/talkinghead_v2/retarget.py): explicit source/target rig identities and calibrated matrix/bias/bounds, plus regularized bounded landmark fitting with explicit correspondences. Jaw/head remain rigid transforms, separate from blendshape channels. Procedural calibration fixtures verify these operations; no Claire-to-FLAME profile was fitted or declared valid. Neutral idle/listening is the default; optional bounded upper-channel test behavior cannot own protected articulation channels.
- [CPU mesh renderer](../src/talkinghead_v2/rendering/mesh.py): blendshape deformation, rigid jaw rotation around the declared pivot, head pose, explicit orthographic camera and triangle depth rasterization to immutable RGB bytes. This implements a timing fallback, not a Gaussian or photorealistic renderer. Near-plane clipping and unknown pose conventions fail explicitly.
- [Motion/video timelines](../src/talkinghead_v2/rendering/timeline.py): independent motion/render cadences, bounded future time and items, valid-interval interpolation, monotonic audio playhead, stale-video dropping and cancellation fences for completed CPU frames. CPU ownership cannot establish CUDA surface lifetimes or physical-device flushing.
- [Executable replay](../src/talkinghead_v2/avatar_replay.py): either a procedural audio/flash calibration or hash-verified cached Qwen pilot PCM → stateful 24-to-16 kHz branch → context windows; independently timestamped procedural controls → mesh frames, a bounded video mailbox and offline audio/video files. Audio is preserved. Test-pattern visual controls are not inferred phonemes, lip synchronization or a replacement motion model.

The packaged [fixture manifest](../src/talkinghead_v2/fixtures/p03-avatar/avatar.json) and [numeric mesh](../src/talkinghead_v2/fixtures/p03-avatar/mesh.json) describe an eight-vertex mathematical shape with a rectangular opening. It contains no human likeness, texture or model weights. It is allowed only for timing fixtures. The manifest explicitly partitions articulation/behavior channel authority; behavior composition preserves speech coefficients and rigid jaw pose. All real human/avatar approval and quality gates remain separate.

## Reproduction and observations

From `v2/`, using the existing offline core environment:

```sh
uv sync --locked --offline --python /usr/bin/python3.12
.venv/bin/tha avatar verify \
  --manifest src/talkinghead_v2/fixtures/p03-avatar/avatar.json --tenant procedural
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 .venv/bin/tha avatar replay \
  --output var/qualification/p03-calibration --resolution 128
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 .venv/bin/python -m pytest -q
```

Replay refuses an existing output directory; use a fresh path to retain previous evidence. It writes `audio.wav`, packed `video.rgb`, a mesh-only `mesh.ppm` preview and `report.json`. Core commands require no torch, NumPy, sounddevice, neural assets or network. Importing any new module initializes no model/device/network. A separate inference environment is needed only to read the existing floating-point Qwen WAV through its already pinned soundfile dependency:

```sh
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 runtimes/qwen-reference/.venv/bin/tha avatar replay \
  --output var/qualification/p03-qwen-short --resolution 128 \
  --wave var/qualification/native-waves-serial/native-000.wav \
  --tts-report benchmarks/reports/p02-native-cohort.json --case short
```

The recorded input must match the request's exact PCM hash and length and declare the synthetic-reference Qwen pilot. There is no TTS model execution in this command. The currently implemented replay intentionally refuses arbitrary human recordings without that provenance boundary. Rights for a real avatar/voice will use the actual asset lifecycle rather than a fixture loophole.

Observed [procedural replay](../benchmarks/reports/p03-calibration.json): 72,000 source samples at 24 kHz, 180 context windows, 90 frames at 30 FPS/128², and a 50 Hz procedural motion cadence. Observed [recorded-Qwen replay](../benchmarks/reports/p03-qwen-short.json): **66,645 source samples**, **167 context windows**, **84 video frames** and 15 EOF windows with model-only right padding. Both retained at most **8,619 / 8,640 context samples**, **three / 64 motion items** within a 500 ms future bound, and **one / three video frames** within a 100 ms future bound. Completed stale motion/video callbacks were rejected after cancellation.

With the selected 20 ms source chunks and the FIR's 32-source-sample right context, the first window became available after **6,720 native samples (280 ms of generated audio)**. Mapping that requirement to the saved native callbacks gives **259.15 ms after text submission** for this recorded case. This reuses P02's callback observation; it does not measure new live inference or include Claire execution, retargeting, rendering lead or device presentation.

Each rendered frame has the intended audio PTS; zero logical file skew is an exact scheduling check, **not measured presentation skew**. The 30-minute test advances a virtual clock over **108,000 motion frames** with at most two retained history items. It is not a wall-clock A/V soak. CPU render service times in the replay reports were collected alongside other CPU qualification jobs and establish no performance profile or frame-deadline pass.

To mux the already generated private files using the installed FFmpeg:

```sh
ffmpeg -hide_banner -loglevel error -n \
  -f rawvideo -pixel_format rgb24 -video_size 128x128 -framerate 30 \
  -i var/qualification/p03-qwen-short/video.rgb \
  -i var/qualification/p03-qwen-short/audio.wav \
  -c:v ffv1 -c:a pcm_f32le var/qualification/p03-qwen-short/preview.mkv
ffmpeg -hide_banner -loglevel error -n \
  -i var/qualification/p03-qwen-short/mesh.ppm -frames:v 1 \
  var/qualification/p03-qwen-short/mesh.png
.venv/bin/python scripts/verify_avatar_replay.py \
  --directory var/qualification/p03-qwen-short --publish benchmarks/reports
```

Mux/demux verification checked all 66,645 decoded float32 samples against P02's PCM hash and counted 84 decoded video frames at 128². The [reusable verifier](../scripts/verify_avatar_replay.py) independently compares decoded container/source audio, every RGB byte and stream count/cadence/dimensions, with bounded memory and decoder deadlines. It can explicitly export only this non-human pilot's metrics. This preserves the complete source audio, with the final video frame extending less than one frame interval past its valid end. No physical output or lip quality claim follows from the file. Raw audio, RGB, PNG and container files remain under ignored `var/`; only non-biometric fixture metadata and synthetic-pilot metrics are committed.
