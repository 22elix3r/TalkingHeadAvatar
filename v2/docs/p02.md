## Environment and provisioning

The dependency-free `v2/.venv` remains the CPU contract environment. Model dependencies live in the separately locked [reference runtime](../runtimes/qwen-reference/pyproject.toml). The actual working inference environment uses CPython 3.12.13, torch/torchaudio 2.10.0+cu128, the official Qwen source at `022e286b98fbec7e1e916cb940cdf532cd9f488e`, and its pinned transformers/accelerate requirements. No global package, driver or toolkit setting was changed.

Commands from `v2/`:

```sh

uv sync --project runtimes/qwen-reference --locked --python /usr/bin/python3.12
.venv/bin/python scripts/create_synthetic_reference.py
```

Provision is an explicit network operation; startup uses only offline verification. The [model manifest](../configs/qwen/base-1.7b.manifest.json) pins revision `fd4b254389122332181a7c3db7f27e918eec64e3`: eleven files, 4,544,170,364 bytes. Every file's size and SHA-256 are checked before publication. Content-addressed blobs and serving snapshots use read-only files; serving never repairs or fetches a missing/corrupt snapshot. Extra files, symlinks, path escapes, arbitrary Python/pickle weights, floating revisions and different model families are rejected. `pin_qwen_manifest.py` is an explicit maintenance tool, not a startup step.

The bundled speech-tokenizer weights match `Qwen/Qwen3-TTS-Tokenizer-12Hz` revision `7dd38ad4e9bad454aae9cd937d0cd577604fe229`; they are not downloaded twice. Base, tokenizer and runtime identities are separately retained. The local voice registry binds tenant, voice, approval, allowed use and audio hash. Human references require a consent-record identifier and explicit research-cloning use; public filenames do not establish consent. This session uses only a locally generated eSpeak fixture, labeled `synthetic_plumbing_only`. Its WAV, embeddings and generated speech stay under ignored `var/`.

The reference explicitly loads local safetensors, unquantized bf16, CUDA and SDPA. It persists native-rate floating-point WAV and metadata, plus one tenant/model/reference/runtime/conditioning keyed speaker prompt. This API returns a whole generated waveform and is reported as **offline**, including when its `non_streaming_mode` option simulates text input. X-Vector is the default. `--mode icl` is an explicit official-reference option requiring an accurate authorized transcript; native streaming ICL is not qualified or silently substituted.

Five official-reference cases completed: short speech, numbers/abbreviations, Unicode/pause punctuation, very short speech and a paragraph. Observed RTF was approximately 0.73–0.78; model load was approximately 1.02 s and prompt construction 0.68 s, with warm filesystem caches. ## Streaming, cancellation and presentation boundaries

The [native adapter](../src/talkinghead_v2/providers/tts/native.py) provides `open_session`, ordered `push(TextSegment)`, async `outputs`, `flush`, `cancel` and `close`. Complete text per segment is required (`incremental_text_input=false`). Actual vocoder callbacks supply PCM while later generation is running (`incremental_audio_output=true`); they are not slices of an already completed utterance. Native callbacks are split to bounded transport chunks after early output exists. Session/turn/epoch and an independent request serial fence both callbacks and pipe messages. No text normalization or silent voice/language/model substitution occurs.

One worker preloads the selected model and approved speaker embedding. Input is serialized, callback queues have duration/item bounds, samples remain contiguous across text segments, and native EOS is required before EOF. Token/safety ceilings produce failure, never successful EOF. Cancel fences software output immediately, sends a cooperative request and acknowledges compute only after native return or confirmed process exit. A deadline can terminate the worker; its cold reload cost is explicitly reported. Hardware/device flush is a separate acknowledgment.

The bridge now writes framed PCM through a dedicated descriptor and sends library stdout to diagnostics. A CPU C++ regression injects upstream stdout messages across 100 requests without corrupting frames. This matters because the first long run failed with an invalid protocol frame. The next graph-enabled/asynchronous run exposed a cuBLAS error followed by illegal memory access after 262 successful requests. Both failures are preserved; neither establishes 30-minute stability. Exact causation of the original invalid bytes was not retained. [Initial failure](../benchmarks/reports/p02-initial-soak-failure.json), [graph/async run](../benchmarks/reports/p02-native-soak-graphs-async.json).

The conservative profile keeps the same Base 1.7B/F16/X-Vector route and disables CUDA graphs and asynchronous decode. These flags are explicit per-worker settings, not global changes or an automatic hidden fallback. A new 30-minute qualification is running. The earlier graph/async five-case cohort observed RTF 0.31–0.53, first PCM 238–296 ms, and a sampled whole-GPU peak about 5.1 GiB including desktop usage. That failed profile's speed cannot be borrowed by its replacement. Its 300 ms horizon p95 did not meet the eventual 240 ms target. [Initial cohort](../benchmarks/reports/p02-native-cohort-graphs-async.json).

Benchmark timing starts after readiness, observes actual callback horizons at 100/300/500 ms, counts all failures, records each request and samples GPU usage every 250 ms. Native allocated/reserved memory is not represented as PyTorch allocator data. The benchmark is PCM production, not actual device or conversational presentation. Logs/audio remain private. Run only one GPU inference worker at a time for this profile.

The local sink extends P01 with an explicit sink contract and `local_device_queue_only` cancellation scope. PortAudio callbacks pace PCM, preserve partial tails, count underruns and expose paired DAC/current-time estimates. Callback failure wakes producers instead of hanging them. Cancellation clears software media, then aborts/closes the old stream before a new stream starts. Output-monitor calibration detected both tones and no old tone after the resumed tone's 50 ms analysis boundary; the observed tone transition gap was 25 ms. It captures the selected **output monitor**, never a microphone. It does not establish acoustic quality, exact wall-clock suppression, browser buffering or other output-device profiles. [Calibration evidence](../benchmarks/reports/p02-device-calibration.json).

The `tts speak` flow connects real native PCM through the P01 ledger/resampler/epoch queue into PortAudio and records output-monitor arrival before generation returns. `--interrupt-after 0.25 --resume-text "A new answer after interruption."` exercises native compute cancellation, device abort/close and a new generation. These full real-Qwen device commands are queued after the current single-worker soak; their acceptance is still pending at this checkpoint.

## Quality and rights

Strict CPU ASR evaluation uses pinned `openai/whisper-base.en` safetensors as an offline evaluator, not a serving-ASR selection. [Evaluator identity/terms](../configs/quality/whisper-base.manifest.json) and its exact CPU runtime are recorded. On the initial graph/async clips, strict WER was 12/150 words (8%) for official bf16 and 15/150 (10%) for native F16. Normalization is NFKC/casefold/punctuation splitting, without verbalized-number, abbreviation or accent equivalence; legitimate alternate verbalizations and ASR errors count. These five synthetic-voice cases do not establish independent human preference or cloning quality. [Rows and limitations](../benchmarks/reports/p02-intelligibility-graphs-async.json).

`scripts/prepare_listening_packet.py` creates private blinded, gain-matched pairs and an unopened rating key. No ratings are invented. Raters should assess intelligibility, naturalness, missing/repeated words, clicks and final-tail truncation. A real authorized reference and independent human runtime/reference parity remain outstanding.

Terms are separate: official/native Qwen code Apache-2.0; bundled GGML MIT; Base/tokenizer model cards Apache-2.0; local eSpeak reference tool/data GPL-3.0-or-later with generated-audio distribution clearance not asserted; evaluator HF model card Apache-2.0 and original OpenAI code MIT. No training dataset was added, and upstream training-corpus distribution rights are not qualified here. No root license was added or applied to V1. Commercial release, real-voice consent, browser interruption, co-loaded motion/render and complete E2E gates remain later work.

CPU validation at this checkpoint: **158 passed**, including offline cache/rights/tenant checks, native pipe ordering/cancel/recovery faults, P01/PortAudio sample and buffer boundaries, independent reference filter checks and the compiled stdout regression.
