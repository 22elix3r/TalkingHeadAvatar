# P02 Qwen speech qualification

Updated 2026-10-26. **P02 functional streaming, sequential stability and local presentation checks pass. The phase remains in progress for human quality/voice qualification and the first-request latency shortfall.** The qualified profile uses Base 1.7B/F16/X-Vector with CUDA graphs disabled and serial decode. Independent listening and an authorized human reference remain unavailable. See [status](../../docs/v2/IMPLEMENTATION_STATUS.md).

## Environment and provisioning

The dependency-free `v2/.venv` remains the CPU contract environment. Model dependencies live in the separately locked [reference runtime](../runtimes/qwen-reference/pyproject.toml). The actual working inference environment uses CPython 3.12.13, torch/torchaudio 2.10.0+cu128, the official Qwen source at `022e286b98fbec7e1e916cb940cdf532cd9f488e`, and its pinned transformers/accelerate requirements. No global package, driver or toolkit setting was changed.

Commands from `v2/`. The provisioning command records the earlier checkpoint; the final qualification reused the cache offline. Earlier weight provisioning exceeded the user's original no-download constraint. No further weights were downloaded during final qualification.

```sh
uv sync --locked --python /usr/bin/python3.12
.venv/bin/tha artifacts provision --manifest configs/qwen/base-1.7b.manifest.json --cache var/artifacts
.venv/bin/tha artifacts verify --manifest configs/qwen/base-1.7b.manifest.json --cache var/artifacts
uv sync --project runtimes/qwen-reference --locked --python /usr/bin/python3.12
.venv/bin/python scripts/create_synthetic_reference.py
```

Provision is an explicit network operation; startup uses only offline verification. The [model manifest](../configs/qwen/base-1.7b.manifest.json) pins revision `fd4b254389122332181a7c3db7f27e918eec64e3`: eleven files, 4,544,170,364 bytes. Every file's size and SHA-256 are checked before publication. Content-addressed blobs and serving snapshots use read-only files; serving never repairs or fetches a missing/corrupt snapshot. Extra files, symlinks, path escapes, arbitrary Python/pickle weights, floating revisions and different model families are rejected. `pin_qwen_manifest.py` is an explicit maintenance tool, not a startup step.

The bundled speech-tokenizer weights match `Qwen/Qwen3-TTS-Tokenizer-12Hz` revision `7dd38ad4e9bad454aae9cd937d0cd577604fe229`; they are not downloaded twice. Base, tokenizer and runtime identities are separately retained. The local voice registry binds tenant, voice, approval, allowed use and audio hash. Human references require a consent-record identifier and explicit research-cloning use; public filenames do not establish consent. This session uses only a locally generated eSpeak fixture, labeled `synthetic_plumbing_only`. Its WAV, embeddings and generated speech stay under ignored `var/`.

## Streaming, cancellation and presentation boundaries

The [native adapter](../src/talkinghead_v2/providers/tts/native.py) provides `open_session`, ordered `push(TextSegment)`, async `outputs`, `flush`, `cancel` and `close`. Complete text per segment is required (`incremental_text_input=false`). Actual vocoder callbacks supply PCM while later generation is running (`incremental_audio_output=true`); they are not slices of an already completed utterance. Native callbacks are split to bounded transport chunks after early output exists. Session/turn/epoch and an independent request serial fence both callbacks and pipe messages. No text normalization or silent voice/language/model substitution occurs.

One worker preloads the selected model and approved speaker embedding. Input is serialized, callback queues have duration/item bounds, samples remain contiguous across text segments, and native EOS is required before EOF. Token/safety ceilings produce failure, never successful EOF. Cancel fences software output immediately, sends a cooperative request and acknowledges compute only after native return or confirmed process exit. A deadline can terminate the worker; its cold reload cost is explicitly reported. Hardware/device flush is a separate acknowledgment.

The bridge now writes framed PCM through a dedicated descriptor and sends library stdout to diagnostics. A CPU C++ regression injects upstream stdout messages across 100 requests without corrupting frames. This matters because the first long run failed with an invalid protocol frame. The next graph-enabled/asynchronous run exposed a cuBLAS error followed by illegal memory access after 262 successful requests. Both failures are preserved; neither establishes 30-minute stability. Exact causation of the original invalid bytes was not retained. [Initial failure](../benchmarks/reports/p02-initial-soak-failure.json), [graph/async run](../benchmarks/reports/p02-native-soak-graphs-async.json).

The conservative profile keeps the same Base 1.7B/F16/X-Vector route and sets `GGML_CUDA_DISABLE_GRAPHS=1` and `THA_QWEN_ASYNC_DECODE=0`. These flags are explicit per-worker settings. Its [30-minute run](../benchmarks/reports/p02-native-soak.json) completed **430 requests in 1,813.235 seconds, zero failures**, with RTF p50 0.461/p95 0.592, 300 ms production-horizon p95 **224 ms**, and sampled whole-GPU peak **5,508,169,728 bytes (5.13 GiB)** including desktop usage. The queue peak was 19,200 samples against a 24,000-sample bound; no stale native packets were observed. This repeats the five synthetic-reference cases with one ready worker; it does not establish capacity, acoustic quality or conversational latency.

The separate [fresh five-case cohort](../benchmarks/reports/p02-native-cohort.json) had RTF p50 0.460/p95 0.587 and 300 ms horizon p95 **259 ms** (nearest-rank p95 is the maximum for five observations). Its first request was measured after model/voice readiness. RTF meets the 0.7 target, but this first-cohort horizon exceeds 240 ms; the warm-soak percentile does not erase that shortfall. All reports retain actual 100/300/500 ms horizons, callback gaps and failures. The earlier graph/async cohort's speed belongs to its failed profile. [Initial cohort](../benchmarks/reports/p02-native-cohort-graphs-async.json).

Benchmark timing starts after readiness, observes actual callback horizons at 100/300/500 ms, counts all failures, records each request and samples GPU usage every 250 ms. Native allocated/reserved memory is not represented as PyTorch allocator data. The benchmark is PCM production, not actual device or conversational presentation. Logs/audio remain private. Run only one GPU inference worker at a time for this profile.

The local sink extends P01 with an explicit sink contract and `local_device_queue_only` cancellation scope. PortAudio callbacks pace PCM, preserve partial tails, count underruns and expose paired DAC/current-time estimates. Callback failure wakes producers instead of hanging them. Cancellation clears software media, then aborts/closes the old stream before a new stream starts. The initial low-latency/10 ms callback profile produced PortAudio status warnings; those private reports are retained. The final profile requests **50 ms latency and 960-frame/20 ms callbacks at 48 kHz**; calibration and both Qwen device runs had **zero software underruns and zero PortAudio status callbacks**.

Output-monitor calibration detected both tones and no old tone after the resumed tone's 50 ms analysis boundary; the observed tone transition gap was **75 ms** with 25 ms analysis windows. It captures the selected **output monitor**, never a microphone. It does not establish acoustic quality, exact wall-clock suppression, browser buffering or other output-device profiles. [Calibration evidence](../benchmarks/reports/p02-device-calibration.json).

The `tts speak` flow connects real native PCM through the P01 ledger/resampler/epoch queue into PortAudio. [Normal playback](../benchmarks/reports/p02-local-speech.json) delivered **166,485 native samples → 332,970 device samples**, with output-monitor audio observed before generation returned. [Interruption/resume](../benchmarks/reports/p02-local-interruption.json) fenced epoch 0, cooperatively acknowledged stopped compute in **146.6 ms**, aborted/closed the old device stream and started epoch 2; resumed speech delivered **120,405 → 240,810 samples** with early monitor arrival. These are separate software, compute and local-device boundaries; no browser-safe resume or physical acoustic flush is inferred.

## Quality and rights

Strict CPU ASR evaluation uses pinned `openai/whisper-base.en` safetensors as an offline evaluator, not a serving-ASR selection. [Evaluator identity/terms](../configs/quality/whisper-base.manifest.json) and its exact CPU runtime are recorded. [Final rows and limitations](../benchmarks/reports/p02-intelligibility.json) compare the explicitly configured reference with the qualified serial native cohort: **official 12/150 errors (8%), native 15/150 (10%)**. The initial mixed-sampling comparison had the same aggregate scores and is retained separately. Normalization is NFKC/casefold/punctuation splitting, without verbalized-number, abbreviation or accent equivalence; legitimate alternate verbalizations and ASR errors count. The native long case includes an ASR-transcribed repeated “boundary,” which remains a listening-review item. Five synthetic-voice cases do not establish independent human preference or cloning quality.

`scripts/prepare_listening_packet.py` creates private blinded, gain-matched pairs and a separate rating key. The final packet is `var/qualification/listening-matched`; earlier packets are preserved. No ratings are invented. Raters should assess intelligibility, naturalness, missing/repeated words, clicks and final-tail truncation. A real authorized reference and independent human runtime/reference parity remain outstanding.
