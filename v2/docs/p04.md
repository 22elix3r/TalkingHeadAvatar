# P04 browser audio reference

Updated 2026-10-27. **In progress.** A real local browser audio path now connects microphone/typed input, CPU ASR, a configured CPU LLM, Qwen3-TTS and a self-hosted LiveKit receiver. The browser shows a static procedural reference, explicitly labeled as audio mode. The missing Claire/authorized-avatar/retarget inputs from P03 still prevent the speaking-avatar and aligned A/V acceptance gate. This is not a complete P04/M2 or release pass. [Current status](../../docs/v2/IMPLEMENTATION_STATUS.md).

## What runs

The [React/TypeScript client](../web/src/main.tsx) provides microphone permission/preflight, device selection, typed recovery, live revised/final captions, stop/interrupt/mute, autoplay recovery and safe reconnection through a new session. It lazy-loads the LiveKit client after interaction. Captions are bounded in browser/server memory; default recording is off. The UI distinguishes its synthetic demo voice and static visual from a qualified speaking avatar. No API key, database credential, reference embedding or model path is bundled into the page.

[FastAPI endpoints](../src/talkinghead_v2/server/app.py) implement capabilities/assets, loopback development login, idempotent session creation, preparation/readiness, tenant-scoped status, restricted join grants, bounded SSE events, sequenced epoch-checked controls, browser heartbeat and idempotent close. Development mode checks peer, Host, Origin, CSRF and bounded request bodies, including chunked bodies. It cannot be configured with public service endpoints; the supplied server binds only `127.0.0.1:18700`. This is local development identity, not production login.

[PostgreSQL metadata](../src/talkinghead_v2/server/db.py) and the [frozen initial migration](../runtimes/session-api/migrations/versions/0001_sessions.py) persist principals, fixture asset revisions, sessions, idempotency outcomes and control results. Asset revisions pin the verified TTS runtime descriptor, including conditioning/model bindings. Raw PCM, transcripts and prompts are not stored in these tables. Atomic admission permits **one** active/preparing local session; this is a conservative configured limit, not a measured capacity result. Fencing fields reject stale durable writes. Cross-process/native lease enforcement and distributed admission remain later gates.

The [actor](../src/talkinghead_v2/server/actor.py) owns transcript revisions, current utterance, generation epoch, bounded text queue, cancellation and resource cleanup. Preparation is cancellable; concurrent close requests stop sources once. A lost durable close reports pending persistence after source shutdown. Unjoined sessions expire after 30 seconds; missing browser heartbeats close a session within the 30-second grace plus the two-second lease poll. Closed actors and SSE streams release their caption buffers. API startup fences/reconciles orphaned sessions instead of replaying their speech.

## Actual providers and limits

The separately locked [session runtime](../runtimes/session-api/pyproject.toml) keeps FastAPI/LiveKit/PostgreSQL/ASR dependencies out of the zero-dependency CPU core and the P02 official-reference environment. [Source identities](../configs/p04/source-lock.json) bind the observed cache/images; `uv.lock` and `package-lock.json` record actually installed/tested dependencies.

- **ASR:** cached `Systran/faster-whisper-base.en` revision `3d3d5dee26484f91867d81cb899cfcf72b96be6c`, copied/hashed into a private read-only local snapshot; CTranslate2 CPU/int8 with two threads. This is explicitly **rolling-window transcript revision**, not a native token-streaming decoder. Partial decoding runs while input is still arriving; final decoding uses the bounded complete turn. It is not a final transcript sliced into fake partials. The single CPU decode slot remains held until native decode returns even when the coroutine is cancelled. `local_files_only=True`; `vad_filter=False` prevents use of the bundled neural VAD.
- **VAD/endpoint:** WebRTC VAD on 20 ms, mono PCM16/16 kHz frames. A 1.2-second silence policy preserves the 200/500/1000 ms logic fixtures, with a 30-second input bound and explicit maximum-utterance reason. This patience exceeds the design endpoint budget. There is no natural-human false-cutoff/backchannel-rate qualification. [Policy/segmenter](../src/talkinghead_v2/conversation.py).
- **LLM:** the already cached Ollama `qwen3:14b`, Q4_K_M, digest `bdbd181c33f2ed1b31c972991882db3cf4d192569092138a7d29e973cd9debe8`. This is an explicitly configured CPU reference rather than the planned 4B profile. Each request sets `num_gpu=0`, four CPU threads, 2,048 context tokens, 80 output tokens and thinking off. Startup verifies the cached digest and `size_vram=0`; it never calls a pull endpoint or changes Ollama's global configuration. The adapter consumes actual streamed text. It retains at most four user turns; assistant history is omitted until receiver presentation acknowledgments are qualified, so generated/cancelled words are not treated as heard.
- **Segmentation/TTS:** committed complete-word clauses, protected decimal/abbreviation handling and a two-segment queue; release after eligible words and the 120 ms timer, with a complete final tail. Actual word arrival can exceed that target. Speech remains the qualified P02 **Qwen3-TTS Base 1.7B/F16/X-Vector** profile with graphs disabled and serial decode. The same per-session native worker stays loaded over turns; a new admitted session currently reloads it. No alternate serving TTS was introduced.

ASR/LLM code and model terms are separately recorded: Faster-Whisper/CTranslate2 and the Whisper conversion use their upstream MIT terms; this cached Qwen LLM reports Apache-2.0. The existing Qwen TTS and synthetic voice/tool provenance remains attached through P02. This does not clear training-corpus, human-reference or commercial distribution rights. No root license was applied to unrelated work.

**Constraint deviation:** installing the Faster-Whisper dependency also downloaded its **unused 1,245,151-byte `silero_vad_v6.onnx`** bundled in the wheel. It is disabled and was not loaded, but this installation was not literally free of new weight files. Its hash and this deviation are in the source lock. All **serving** ASR/LLM/TTS checkpoints came from existing caches; no model-hub provisioning or new serving checkpoint download occurred. Future startup remains offline for model assets. Software packages and the pinned LiveKit service image were provisioned separately from model artifacts.

## Media and receiver cancellation

[LiveKit reference transport](../src/talkinghead_v2/server/transport.py) uses distinct browser, controller and media identities with room-scoped, two-minute grants. Only the expected user's microphone is subscribed for ASR; avatar output is excluded. The publisher uses actual early native PCM, P01 ledger/stateful resampling, a 60 ms sender audio queue and explicit valid/codec-padding accounting. CPU RGB video is a static procedural fixture, not inferred articulation; no GPU-copy or lip-sync claim follows.

The inspected LiveKit Python SDK's `RingQueue` silently evicts on overflow. A source-owned, version-pinned receive-queue adapter replaces that behavior: a 25-frame/500 ms overflow clears the failed input with an explicit discontinuity and terminates the session. It never quietly transcribes dropped speech. This uses a guarded private SDK integration point and must be requalified on SDK upgrades; opaque vendor/network queues are not a proven end-to-end memory bound.

Intentional interruption gates/detaches browser output immediately, fences actor/native/media output, cancels LLM/TTS work and unpublishes old tracks. The next answer has new audio/video track IDs and an explicit new epoch/clock mapping. The [receiver gate](../web/src/playback.ts) rejects late old bindings and old track callbacks, including those arriving while HTTP cancellation is pending. A cancel acknowledgment alone never unmutes playback. Control/SFU/network interruption requires a new session; the app does not automatically replay old buffers on reconnect. Device changes stop the old session first. Physical speaker suppression ≤200 ms and a browser acoustic safe-resume bound are **not** established by these software checks.

## Run locally

From `v2/`, with the already cached serving models and installed Node 24/Python 3.12/Docker/Ollama:

```sh
uv sync --project runtimes/session-api --locked --offline --python /usr/bin/python3.12 --default-index https://pypi.org/simple
cd web
npm ci --offline --no-audit --no-fund
npm run build
cd ..
.venv/bin/python scripts/p04_local.py init
.venv/bin/python scripts/p04_local.py up
THA_P04_CONFIG="$PWD/var/p04/runtime.json" runtimes/session-api/.venv/bin/python \
  -m alembic -c runtimes/session-api/alembic.ini upgrade head
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 runtimes/session-api/.venv/bin/python \
  scripts/serve_p04.py --config var/p04/runtime.json
```

`init` is one-time and refuses to overwrite configuration/secrets. Existing initialized workspaces start with `up` and the server command. Initial package installation requires an explicit online dependency sync if those software packages are not cached; it also has the bundled-weight caveat above. Missing model caches fail without fetching. Private files live under ignored `var/p04/` with restricted permissions. The isolated Compose project is `tha-v2-p04`; it does not reuse or modify other running databases/services. PostgreSQL and LiveKit exposed ports bind to loopback. `scripts/p04_local.py down` stops only this project and retains its volume.

Open **http://127.0.0.1:18700**. Start with the microphone or choose typed messages. Allow audio when prompted. End the session to release its Qwen worker. Browser speech may be interrupted with the dedicated button or a qualified VAD barge-in; actual natural-human interruption/echo behavior still needs evaluation. Do not expose this development profile publicly.

## Validation and remaining acceptance

The CPU core suite passed **212 tests** without model downloads or inference dependencies. The isolated runtime passed **six PostgreSQL/API/queue/fault tests** with providers explicitly replaced for API boundary tests. Real model evidence comes separately from actual Chromium/LiveKit/ASR/LLM/Qwen browser runs. PostgreSQL migration downgrade/upgrade was exercised only in the dedicated `tha_p04_test` database. Browser unit tests verify that old epochs, old tracks and cancellation acknowledgments cannot authorize receiver resume.

Controlled browser fixtures exercise typed conversation, synthetic microphone input, complete received speech, fresh track IDs after interruption, native microphone permission denial, injected autoplay failure/user recovery, network disconnection, device change and cancellation during preparation. Chromium uses the installed executable; no browser binary is fetched by the tests. The microphone fixture uses locally generated eSpeak input, not a real person's recording and not an alternate serving TTS. The harness explicitly records only the synthetic test's received answer; application recording remains off.

An initial eSpeak sky-question case failed: offline ASR read “Cleodate Times guy,” and browser ASR read “clear day times guy.” That failure is retained. The separately labeled arithmetic plumbing case produced **“What is 2 plus 2?” → “2 plus 2 is 4.”** ASR of the browser-received Opus recording confirmed the final “4.” This does not establish WER/naturalness or human voice quality over a population. Harness setup/locator failures were corrected without relabeling the ASR failure as a pass.

The controlled latency probe measured **3,406.1 ms** from last nonzero microphone **WebAudio observation → first nonzero received WebAudio observation**, in one browser performance clock. This is one observation with 20 ms polling, FFT-window delay and uncalibrated device/graph/acoustic offset. It does not annotate first meaningful-word onset or actual acoustic presentation. No p50/p95/p99 or client-acoustic audiovisual SLO pass is inferred. The conservative endpoint policy and cached CPU 14B LLM currently miss the intended low-latency profile; retain the measured shortfall. Ollama's five-minute request keepalive also means an answer after prolonged idle may include a reload; no unconditional warm-latency claim is made.

[Stored qualification](../benchmarks/reports/p04-browser-reference.json) includes seven passing real-browser checks, source/lock hashes, actual runtime versions, the received-answer transcription, fixture/receiver hashes and the retained ASR failure. The [exported OpenAPI](p04-openapi.json) describes implemented routes/request schemas; loopback/cookie/CSRF enforcement is also implemented in middleware and route ownership checks. `scripts/qualify_p04.py` verifies the real browser result, JUnit evidence and recorded synthetic answer before exporting metrics; it never exports raw media.

The database tests require the separately initialized/migrated `var/p04/test-runtime.json` pointing to `tha_p04_test`; they refuse to reset the running reference database. Browser fixtures require the private pre-generated microphone WAV and real services ready; the readiness barrier fails rather than substituting providers. Raw microphone/answer media, screenshots, database files, keys and browser artifacts remain under ignored `var/`. Public reports contain only synthetic-fixture metrics and source identities.

On a fresh fixture directory, `.venv/bin/python scripts/create_p04_microphone_fixture.py --directory var/p04` reproduces the declared synthetic input with installed eSpeak NG/FFmpeg. It refuses to overwrite existing input. To create the separate test database, use `docker exec tha-v2-p04-postgres-1 createdb -U tha tha_p04_test`; copy the private runtime JSON to `test-runtime.json` with only its database name changed to `tha_p04_test`, retain mode `0600`, then run the same Alembic upgrade with `THA_P04_CONFIG` pointing to that test file. Never use the application's `tha_v2` database for resettable tests.
