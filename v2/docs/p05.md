## Runnable path

Use the isolated P04 services and session runtime from [the local runbook](p04.md). Before starting the new server, apply the additive migrations from `v2/`:

```sh
THA_P04_CONFIG=var/p04/runtime.json runtimes/session-api/.venv/bin/alembic \
  -c runtimes/session-api/alembic.ini upgrade head
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 runtimes/session-api/.venv/bin/python \
  scripts/serve_p04.py --config var/p04/runtime.json
```

Startup requires migration `p05_0003` before loading providers. `p05_0002` adds lifecycle tables; `p05_0003` records attempt/fence history. Both migrations were frozen and applied against actual PostgreSQL. Downgrade/upgrade validation uses only `tha_p04_test`; do not downgrade the live database. A private pre-P05 `pg_dump -Fc --no-owner` backup was retained under ignored `var/p05/`; this is not a qualified restore/backup-retention gate.

For a non-biometric example, package the repository's first-party mathematical mesh:

```sh
.venv/bin/python scripts/package_mesh_import.py \
  --manifest src/talkinghead_v2/fixtures/p03-avatar/avatar.json \
  --output var/p05/timing-bundle.json
```

The command validates the source and refuses to overwrite its output. It neither changes source assets nor grants consent. Open **http://127.0.0.1:18700/**, expand **Manage avatar imports**, enter an asset name and authorization-record reference, choose **Synthetic geometry fixture**, select the JSON bundle, attest to permission, and import. Review the neutral preview and explicit static-reference limitations before approval. Select the approved asset in **Avatar reference**, then start a conversation or typed message. The actual cached Qwen voice and loaded imported neutral mesh are used by the session. Revoking the asset during speech gates the receiver, stops the source, denies new grants and purges owned import/derived objects. The original files supplied by the user are never modified.

The local development identity is reused across reloads and sessions instead of allocating a new tenant at each start. The authentication cookie remains HttpOnly; a separate SameSite CSRF cookie lets tabs reuse the current CSRF token. Mutations still require the exact allowed Origin and the server's CSRF hash. This remains the existing eight-hour pseudonymous development identity, not durable account recovery or hosted OIDC. Clearing/expiring the development cookie does not provide a way to recover that tenant's library. Production identity, memberships and reviewer/operator roles remain P08 work.

## Import contract and boundaries

The upload is a JSON object with exactly `schema_version: 1`, `manifest` and `mesh`; the latter two are literal JSON file texts. This preserves the declared mesh's exact UTF-8 bytes/hash. Its appearance path must be the flat filename `mesh.json`. No ZIP extraction, pickle, vendor loader, remote URL or client-selected filesystem path is accepted. Strict parsing rejects duplicate keys and nonfinite numbers.

The current **static CPU reference profile** accepts up to 4 MiB per bundle, 512 vertices, 1,024 triangular faces and 16 declared coefficients. Larger meshes are explicitly rejected, not truncated. This bound does not qualify a full FLAME/Gaussian import or its serving capacity. Existing canonical checks verify topology/neutral-geometry and basis hashes, coefficient authority/bounds, jaw binding, camera convention and finite geometry. A neutral render must contain visible geometry. These checks establish structural compatibility only; there is no independent held-out likeness, bilabial, teeth or speaking-motion quality score.

Source uploads remain immutable. The importer creates a derived manifest with the authenticated tenant/asset IDs and the actual consent-record reference, preserving geometry, basis and camera conventions. Publication is controlled by database review state rather than an uploaded `approved` string. The immutable revision binds the derived manifest, source mesh, consent generation and the current Qwen runtime-descriptor hash. Running sessions pin that revision. Serving rechecks its authorization and manifest hash; a changed TTS profile needs new review. All imports use the already provisioned synthetic Qwen conditioning. Human/Qwen voice capture and conditioning lifecycle remain unimplemented; no human voice is silently substituted or cloned.

Consent records distinguish a synthetic fixture, consented human likeness and research-authorized asset, with explicit allowed uses and a supplied authorization-record reference. An attestation is a local review record, not independent proof of identity, rights, quality or commercial clearance. Source geometry/texture terms remain separate. Client distribution is disabled.

## Durable behavior

The separate [lifecycle service](../src/talkinghead_v2/server/lifecycle.py), [typed API](../src/talkinghead_v2/server/lifecycle_api.py) and [import worker](../src/talkinghead_v2/server/importer.py) add consent, upload, managed asset/revision, job/attempt, lifecycle-idempotency, outbox and redacted audit tables. Objects stay under tenant-specific directories in private `var/p04/asset-store/`, never the static web root. No raw PCM, transcript, prompt or biometric file contents are put in these tables or routine logs.

Upload grants are scoped to the authenticated tenant/resource, expire after 15 minutes and are stored only as hashes. A retry refreshes the write token without duplicating the upload. Size, media type and exact content hash are checked before sealing. Content is fsynced to a private temporary file and linked atomically without overwriting an existing object. An interrupted write can be retried. There are eight incomplete upload slots and 32 non-revoked imported assets per local tenant; expired incomplete objects are cleaned by the worker.

Enrollment and approval idempotency retain operation/body bindings for 24 hours. The browser reuses operation keys across retries of unchanged forms and approvals, including responses lost after commit. Jobs expose actual validate/export/evaluate/review/published stages, not invented percentages. The CPU-only worker shares no enrollment GPU with active Qwen serving. Attempts use a 30-second lease, monotonic fence and at most three attempts, with 2/4/8-second storage retry delays. An expired owner cannot write/publish after takeover. Cancellation and revocation fence staged writes as well as final publication, so a late attempt cannot recreate deleted private objects.

Revocation commits a tombstone before cleanup. It serializes with approval, locks the serving pointer against reservation, marks affected sessions DRAINING, and permanently fences their publisher before cleanup awaits. DRAINING sessions retain the single admission slot until cleanup. An outbox retries room/source teardown and object purge after interruption; deletion receipts distinguish pending from complete. Consent revocation cascades to managed assets and even sealed uploads that were never enrolled. Tombstones/audit hashes remain; originals outside owned storage and backups are not erased by this receipt. Backup tombstone replay remains unqualified.

The exact self-hosted LiveKit behavior was exercised: a still-valid browser token **can rejoin an empty old room** after application revocation. It recovered no remote tracks because the publisher stopped and the room generation is never reused. New application join grants are denied. This is not instantaneous SFU token invalidation; stronger hosted rejoin enforcement remains a P08 gate.
