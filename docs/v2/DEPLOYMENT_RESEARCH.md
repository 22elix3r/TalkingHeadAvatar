## Framework choice

**Select self-hostable LiveKit for media transport and its client SDKs, with a project-owned session actor and pooled inference adapters.** LiveKit Agents may supply an orchestration baseline or selected adapters, but must not create a complete GPU model stack per session. Its documented per-job process model and CPU-default load policy need adaptation for shared GPU workers. [Agent deployment](https://docs.livekit.io/deploy/custom/deployments/).

**Pipecat is a credible orchestration alternative, not a second mandatory framework.** Its documented transport pairs and SmallWebRTC route are useful for simple self-hosting; managed Daily adds a different dependency. Select it only if a comparison demonstrates lower integration effort without losing sample/epoch control or provider replaceability. Avoid nesting two turn managers or two independently pacing audio pipelines. [Transport comparison](https://docs.pipecat.ai/client/concepts/choosing-a-transport).

**OpenAvatarChat is a reference baseline**, with Apache application code and a separate MIT WebUI; model/asset rights remain independent. Import only individually reviewed components with attribution. A whole-stack fork would inherit chunking, dependencies and model-specific assumptions. [WebUI](https://github.com/HumanAIGC-Engineering/OpenAvatarChat-WebUI/blob/main/README.md).

**Triton is deferred**, not required for the first server. Consider it for a stable stateless/batched model pool when measured utilization warrants it. Readiness, model-control mode and warmup matter; dynamic model-repository writes are not a normal user-facing feature. Stateful TTS/motion cancellation still needs application contracts. [Model management](https://docs.nvidia.com/deeplearning/triton-inference-server/user-guide/docs/user_guide/model_management.html), [secure deployment](https://docs.nvidia.com/deeplearning/triton-inference-server/archives/triton-inference-server-2530/user-guide/docs/customization_guide/deploy.html).

## Operational evidence

- **I:** distributed LiveKit uses Redis, assigns a room to one node and supports draining. This scales rooms, not one infinitely large room. Our GPU admission remains separate. [Distribution](https://docs.livekit.io/transport/self-hosting/distributed/).
- **I:** media UDP/TCP and TURN need explicit firewall/NAT configuration; an HTTPS reverse proxy alone is insufficient. [Ports](https://docs.livekit.io/transport/self-hosting/ports-firewall/).
- **I:** self-hosted removal/permission changes do not revoke already issued tokens. Active-session revocation must stop output, disconnect participants, deny new grants and handle rejoin attempts; token expiry alone is insufficient. [Token lifecycle](https://docs.livekit.io/home/server/generating-tokens).
- **I:** browser microphone capture requires secure context and permission. Video presentation callbacks expose useful metadata but may run late; they are not speaker-sample measurements. [Capture](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia), [video callback](https://developer.mozilla.org/en-US/docs/Web/API/HTMLVideoElement/requestVideoFrameCallback).
- **I:** GPU container CDI is supported; SELinux exceptions can weaken confinement and must not become a blanket Fedora-disable instruction. [CDI](https://docs.nvidia.com/datacenter/cloud-native/gpu-operator/25.3.1/cdi.html), [troubleshooting](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/troubleshooting.html).
- **I:** queue consumers can use PostgreSQL SKIP LOCKED; it is not a general consistency mechanism. Durable enrollment uses explicit leases/idempotent stages, while live media stays off database queues. [PostgreSQL](https://www.postgresql.org/docs/10/sql-select.html).
- **I:** container termination has a grace period; application drains must fit it. Do not assume a default rolling update preserves conversations. [Kubernetes lifecycle](https://kubernetes.io/docs/concepts/workloads/pods/pod-lifecycle/), [agent drain](https://docs.livekit.io/agents/server/options/).

## Still unverified

No native SDK/NVENC/gsplat combination has been built here. No browser cancel-resume boundary has been proven, no deployable photorealistic asset is cleared, and no remote service or host image has been qualified. Pin actual binaries and transitive licenses during implementation. The C++ release and source anchors narrow uncertainty; they are not a tested compatibility lock. SDK drain/metadata support must not be confused with application-level biometric revocation or client playback guarantees.
